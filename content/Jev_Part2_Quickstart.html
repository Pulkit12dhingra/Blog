Your First Jev Evaluation: Playground, API, and Python

Back to Home

This article makes the first Jev request using a support message. We will try the idea in the Playground, then send the same state and Noul question from Python. The goal is to understand the request and answer, not to build the full ticket router yet.

1. Start in the Playground

Open the TypeSafe Playground and sign in. Paste this customer message as the state:

I was charged twice for order A-104. Please refund the duplicate charge.

Add a Noul question asking whether the customer requests a refund. The Playground is useful for trying question wording and inspecting the structured answer before writing application code.

{
  "refund_requested": {
    "type": "noul",
    "instructions": "Does the customer request a refund?"
  }
}

The question ID, refund_requested, is a key for your program. The full judgment is written in instructions.

2. Install the Python SDK and configure a key

The documentation's Python SDK requires Python 3.10 or newer. Install the package with pip:

pip install typesafe-sdk

Create an API key in the TypeSafe console, then expose it to your process as TYPESAFE_API_KEY. For a local macOS or Linux shell:

export TYPESAFE_API_KEY="your-key-here"

Use your real key only in your local environment or a secrets manager. Do not place it in source code, commit it to a repository, or publish it in the tutorial.

3. Send the same evaluation from Python

The SDK reads the API key from the environment. With no model override, its documented default is jev-latest.

from typesafe_sdk import Noul, TypeSafeClient

state = {
    "ticket": {
        "message": "I was charged twice for order A-104. Please refund the duplicate charge."
    }
}

questions = {
    "refund_requested": Noul(
        instructions="Does `ticket.message` request a refund?"
    )
}

with TypeSafeClient() as client:
    response = client.system_one(state=state, questions=questions)

answer = response.answers["refund_requested"]
print(answer.noul)

The code reads the Noul answer from the response using the same ID used in the question map. The printed value is a probability, not a generated sentence and not a final business action.

4. Read the request and response

  • state is the content being evaluated. A string works for a single message; an object is useful when the decision needs named fields or related context.
  • questions is a map of IDs to typed questions. The ID is returned with its answer.
  • model selects the model on the HTTP API. SDK clients default to the documented latest alias.
  • answers contains one typed result per question. Noul uses the noul field.
  • usage reports input and output token counts for the API request.

The actual probability and usage depend on the request and model. Check the response's model field when logging results, since an alias can resolve to a versioned model.

5. Try a small wording change

Change the question to “Does the customer explicitly ask for money to be returned?” and compare the result in the Playground. Then test examples where the customer reports a duplicate charge but does not ask for a refund. This checks whether the wording distinguishes an explicit request from a related complaint.

Do not tune wording against a single message. Keep a small set of representative examples, including clear yes cases, clear no cases, and ambiguous cases. A higher probability on one example does not by itself prove the wording is better.

Keep in mind: No Jev API call was required to write this tutorial. Run the example with your own account, and treat outputs as model judgments that still need application logic and evaluation.
