Jev for Structured Extraction and Verification

Back to Home

Jev is not a text-generation model, so asking it to invent an arbitrary string is the wrong extraction pattern. A safer approach is to use code or another component to find candidate values, let Jev select among those candidates, then parse and validate the selected value in code.

1. Select from values found in the document

Suppose an email contains several addresses and the application needs the one where a receipt should be sent. A regular expression can find the candidate spans. Choice can decide which span matches the requested role. Since every option is copied from the document, Jev selects a value rather than composing a new address.

import re

from typesafe_sdk import Choice, TypeSafeClient

EMAIL_PATTERN = re.compile(r"[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}")

message = "To: billing@example.com. Please send the receipt to sam@example.net."
candidates = list(dict.fromkeys(EMAIL_PATTERN.findall(message)))

if not candidates:
  selected = None
else:
  criteria = {candidate: None for candidate in candidates}
  criteria["none"] = "None of the candidate addresses is the requested value."
  question = Choice(
    instructions="Which email address should receive the receipt?",
    criteria=criteria,
  )

  with TypeSafeClient() as client:
    response = client.system_one(
      state=message,
      questions={"receipt_address": question},
    )

  selected = response.answers["receipt_address"].choice

normalized_address = selected.lower() if selected is not None and selected != "none" else None

In this example, code finds and normalizes the string; Jev resolves the meaning of “send the receipt to.” In production, validate the selected value and handle a low-confidence result according to your application policy.

2. Read date parts, then let code do calendar math

Dates are a useful example of dividing model judgment from exact computation. Jev can classify how a date is expressed and identify a month, day, year, or weekday from finite options. Python should assemble the parts, reject impossible dates, compare dates, and calculate durations.

For a document that says “next Thursday,” a workflow can ask Choice questions about the relative-date form, weekday, and week offset. The application then resolves the date using a documented convention for “next.” If a date component is missing or uncertain, return a review state instead of silently guessing.

3. Verify model-generated structured data

A JSON Schema can confirm that a record has the expected shape. It cannot establish that a value is supported by the source. For a higher-risk extraction pipeline, check each field against the source with focused questions such as whether the value is unsupported, incomplete, or in the wrong format. A verifier should ask one grounded question per potential failure mode, rather than a vague “Is this record good?”

A common cascade is:

  1. Extract using a suitable generative model or deterministic parser.
  2. Validate structural rules in code.
  3. Ask Jev narrow questions about the extracted fields and source.
  4. Accept, request review, or escalate to a stronger model based on an explicitly tested policy.

Keep verification results at field level. One strong problem signal should not disappear inside an average across many correct fields. The escalation rule and threshold are application policy and need validation on labeled records.

4. Boundaries and validation

  • Choice supports a finite option set, with a documented limit of 255 options per question. For a larger candidate set, narrow candidates in stages.
  • Regexes and parsers should find candidates where possible. Candidate generation and selection are separate tasks.
  • Keep arithmetic, normalization, date construction, and schema validation in code.
  • Include missing values and “none of these” outcomes where appropriate.
  • Test hallucinated, incomplete, ambiguous, and correctly absent values.
