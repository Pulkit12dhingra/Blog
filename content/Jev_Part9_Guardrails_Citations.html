Jev for LLM Guardrails and Citation Checks

Back to Home

A generative model may receive unsafe input or produce an answer that overstates its evidence. Jev can add structured checks before or after generation, while application code decides whether to pass, review, or block. This article demonstrates the pattern and its limits.

1. Define narrow checks, not a vague “safe?” prompt

A broad question such as “Is this message safe?” combines multiple policies and makes it difficult to see what triggered a route. Instead, define one Noul per relevant condition, such as whether a message contains a request to override system instructions or asks for a category of advice that your product routes to review.

from typesafe_sdk import Noul, TypeSafeClient

INPUT_CHECKS = {
    "instruction_override": Noul(
        instructions=(
            "Does this message ask the assistant to ignore, reveal, or override its instructions?"
        ),
    ),
    "contains_sensitive_data": Noul(
        instructions="Does this message contain personal or account information?",
    ),
}


def assess_message(text: str) -> dict[str, float]:
    with TypeSafeClient() as client:
        response = client.system_one(state=text, questions=INPUT_CHECKS)
    return {
        key: answer.noul
        for key, answer in response.answers.items()
    }

A similar battery can inspect a generated answer. The application must define what each condition means and how it maps to its policy. Thresholds vary by product, risk, and the cost of review.

2. Keep the action policy in application code

Model probabilities are evidence for a product policy, not the policy itself. A product might pass a low-risk message, send a borderline case to a reviewer, and block a high-confidence policy violation. High-impact or regulated decisions need safeguards appropriate to the domain, not a copied threshold from a tutorial.

Run checks on both input and output when appropriate. An input check does not ensure the model's response is safe, and an output check does not retroactively protect tools or data that the model accessed earlier.

3. Check citations in two stages

Citation verification benefits from splitting mechanical checks from semantic judgments:

  1. Use code to look for the quoted text in the source after normalizing whitespace.
  2. If the quote is found, use Choice to assess whether its surrounding section supports, contradicts, or does not address the claim.
  3. Use confidence and product policy to decide whether to accept the verdict or request human review.

String matching can catch a quote that is absent from a source. It cannot establish that the claim follows from the quote's context. That is the narrower semantic judgment Jev can help with.

from typesafe_sdk import Choice, TypeSafeClient

RELATION = Choice(
    instructions="How does this source section relate to the claim?",
    criteria={
        "supports": "The section states or directly implies the claim is true",
        "contradicts": "The section states the opposite or implies the claim is false",
        "says_nothing": "The section does not address the claim",
    },
)

with TypeSafeClient() as client:
    response = client.system_one(
        state={"claim": claim, "section": source_section},
        questions={"relation": RELATION},
    )

verdict = response.answers["relation"]
if verdict.confidence < 0.80:
    action = "human_review"
else:
    action = verdict.choice

The confidence threshold is illustrative. Test the verifier against known supported, contradicted, unsupported, and fabricated citations. A quote that is present but taken out of context is not necessarily valid evidence.

4. Treat every layer as fallible

Important: Semantic guardrail questions are not a security boundary. Adversarial content can influence a model, and a low risk score does not prove an input is safe. Use defense in depth, keep authorization and tool permissions in deterministic code, and treat retrieved or user-provided content as untrusted.
  • Use the minimum data needed for each evaluation.
  • Do not log secrets or sensitive text without a clear retention policy.
  • Keep human escalation available for uncertain or high-impact cases.
  • Evaluate false positives and false negatives on representative traffic.
